**D83 App-install permission inventory (records existing positioning; mints nothing).** The single enumeration the strict-read-only-subset claim above diffs against: one row per GitHub App permission the D83 App install requests, derived from the prose already in this section and the §11.1 GitHub bundle. The ratified onboarding triplet appears at **read** level so the subset claim is mechanically checkable; the flows beyond onboarding (CI dispatch, status checks, the D56 enrollment flow — §5.2, [§11.1](#111-github-one-bundle) step 5 and its "the two sub-paths on one seam" App-token bullet) account for the remainder of App-install access. Where a flow's exact permission/level is **not** derivable from existing doc prose, the row records its **positioning only** — pending the owning flow's spec — rather than asserting a fresh grant here.

| GitHub App permission | Access level | Consuming flow (derivation) |
| --- | --- | --- |
| `contents:read` | read | Onboarding CI-run-metadata read — the ratified read-only triplet (§5.2 above; doc 07 §2b-spec OQ3). Strict-subset anchor. |
| `actions:read` | read | Onboarding CI-run-metadata read — ratified read-only triplet (§5.2 above). |
| `metadata:read` | read | Onboarding CI-run-metadata read — ratified read-only triplet (§5.2 above). |
| CI dispatch — exact permission/level **recorded positioning pending the owning flow's spec** | write (level not yet derivable) | Non-commit GitHub API calls, CI dispatch ([§11.1](#111-github-one-bundle) App-token bullet, "non-commit GitHub API calls (CI dispatch, status checks)"); the precise write permission this needs is not in existing prose. |
| Status checks — exact permission/level **recorded positioning pending the owning flow's spec** | write (level not yet derivable) | Non-commit GitHub API calls, status-check posting ([§11.1](#111-github-one-bundle) App-token bullet); the precise write permission for posting checks is not in existing prose. |
| D56 enrollment flow — exact permission/level **recorded positioning pending the owning flow's spec** | not yet derivable | The D56 enrollment flow rides the App install (§5.2; [§11.1](#111-github-one-bundle) App-token bullet, "the D56 enrollment flow rides the App install"); its enrollment-action permission is owned by the D56 spec, not asserted here. |

The three `*:read` rows are the **whole** of the read level and carry **no write scope** — so the ratified subset can never widen into a commit, a CI dispatch, or an enrollment action (§5.2 above). The three write/enrollment rows are positioning records, not grants: when their owning flow's spec lands its exact permission, this inventory is the single anchor that row updates against.
